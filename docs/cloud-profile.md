# 备用配置（cloud profile）

云端下发节点，仅本校学生可取。本文记录设计约束与已知风险，避免后续维护者
按错误的心智模型改动。

## 1. 不变量

1. **授权判据只有一个**：请求源 IP 是否属于本校网段。判据在服务端。
2. **仓库里不出现完整入口**：入口由「校园网登录页地址」派生。
3. **云端只提供节点**：`proxies` 之外的字段（tun/dns/rules/端口/controller）
   全部以本地骨架为准，否则会砸掉 ICS 网卡识别、免流绕过与端口预检。
4. **取不到配置时明确报错**，绝不静默降级成裸 WARP 出口。

## 2. 三层，各管一件事

| 层 | 机制 | 挡什么 | 挡不住什么 |
|---|---|---|---|
| 入口派生 | `sha256(salt + 门户地址)` 取 16 位 hex 当子域名 | 爬虫扫仓库找域名、fork 自动继承可用入口 | 任何读代码的人 |
| 源 IP 门禁 | Worker 校验 `CF-Connecting-IP` ∈ 校园段 | 所有校外请求（含外校学生） | 校园网内任何人；已下发的文件 |
| 落盘隔离 | 端口/凭据/规则归本地，云端只有节点 | 配置被整份替换导致的结构性故障 | 节点被转发 |
| 远程总开关 | `notice.json` 的 `cloudProfile`（公告） | 维护者一键停用：不能获取，也不能启动 | 已改过客户端的用户 |

### 2.1 远程总开关

`notice.json` 顶层 `cloudProfile` 是唯一的启停开关，语义 **fail-closed**：

- 显式 `true` 才开放；`false`、字段缺失、公告拉不到且无本机缓存，一律锁定；
- 客户端每次启动拉公告时把它写进 `state/notice-cache.json`（7 天有效），
  启动免流时读这份缓存，而不是再联网一次；
- 锁定后 `/api/v1/cloud-config` 的 PUT 返回 `409 cloud-locked`，
  `/api/v1/proxy/start` 返回 `400 cloud-locked`——即使本地还留着上次的节点。

关掉它不会影响已经起来的 mihomo，只影响下一次启动；要立刻断开，
让用户重启免流或直接停用。

## 3. 派生不是加密

输入是公开常量（校园门户地址本来就是公开信息，公开文档里也出现过），
规则又必须在开源客户端里。所以派生值对任何读过代码的人都是确定的：

- 它的价值是**卫生措施**，不是安全边界；
- 因此 Worker **不校验 slug**。校验会引入 404/200 的枚举判别口（`if 拼对了自然返回`
  正是暴力破解成立的表述），而不校验则连判别口都没有；
- 也因此 `state/`、`settings.json` 里能不存在完整入口就不存在：派生值要时重算即可。

> 结论：**不要**把「子域名保密」写进任何对外承诺。安全边界是源 IP 段。

## 4. 已知风险与处置

| 风险 | 后果 | 处置 |
|---|---|---|
| **v6 回落**：校园网 v6 异常时系统走 v4 出网 | 学生被自己人 403 | `ALLOWED_PREFIXES` 必须同时包含校园公网 v4 出口段（`202.204.0.0/16`、`123.112.10.0/23`） |
| **段值配错** | 全校 403，且客户端只显示「仅对校园网开放」 | 先用 `/whoami` 实测收集，再收敛前缀 |
| **CT 日志**：为具体子域名单独签证书 | `crt.sh` 搜 `%.freev6.cc.cd` 拿到全部 slug | 用通配路由 + 通配证书，不单独签发 |
| **文件转发**：配置落到 `config/cloud-profile.yaml` 后被贴群 | 校外可用 | 无法用门禁解决。只能给每人发不同节点密码 + 定期轮换（可定位泄漏者） |
| **入口变更**：域名/段改了，旧客户端不会自己知道 | 老版本全员失效 | 通过已公开的 `notice.json` 下发新门户地址；停用前先公告 |
| **订阅持久化**：mihomo 把 provider URL 写进配置与日志 | 入口出现在学生磁盘 | 接受；门禁在服务端，入口泄漏不等于可用 |

## 5. 能不能让配置"全程不可提取"

**不能。** 判断依据很硬：客户端必须把节点参数交给 mihomo 才能建连，"能连上" 与
"参数存在于本机" 是同一件事。任何声称做到的方案，要么客户端不能用，要么只是把
明文挪到了另一个位置（内存盘、加密文件、进程内存）。

当前已经做的（提高随手提取的成本）：

| 措施 | 挡什么 |
|---|---|
| 节点只在 `state/mihomo.yaml` + `config/cloud-profile.yaml`，权限 0o600 | 同机其他用户随手读 |
| UI 只显示节点数与打码入口 | 截图外带 |
| 完整入口不写进 `settings.json` | 配置文件被拷走 |
| `external-controller` 只绑 `127.0.0.1` + per-install secret | 本机其他进程通过 9090 拉 `proxies` |

挡不住的：进程内存 dump、管理员权限、抓包看节点地址/SNI、以及用户自己把
`config/cloud-profile.yaml` 发出去。

要再上一档，只能按成本递增：

1. **加密落盘**（DPAPI/AES-GCM，机器+用户绑定）→ 挡"直接拷 state 目录"，挡不住内存。
2. **内存盘 + 启动后删除**→ mihomo 的 `-f` 只读一次，删除后 reload 失效，故障面变大。
3. **per-device 节点凭据（推荐）**：服务端按 deviceId 派生节点密码，定期轮换 →
   泄漏能定位到人、能单点吊销。这是唯一真正降低"被提取后扩散"的手段，且不依赖客户端保密。

结论：把资源投在 3，而不是继续加固 1/2。

## 6. 客户端实现

| 位置 | 作用 |
|---|---|
| `internal/mihomo/endpoint.go` | 归一化门户地址 → 派生入口 URL（黄金值测试锁死规则） |
| `internal/mihomo/cloud.go` | 解析云端 yaml，只取 `proxies`；骨架字段忽略（仅接口内部可见，不在 UI 回报） |
| `internal/mihomo/config.go` | `CloudNodes` 非空 → 不渲染内置接入点、不要求 WARP 凭据 |
| `cmd/freev6-helper/cloudconfig.go` | `GET/PUT/DELETE /api/v1/cloud-config`，403 → `campus-only` |

请求体：

```json
{ "portalHost": "192.0.2.10" }
```

`portalHost` 只存归一化后的裸 host；派生出的完整入口不落盘。刷新时省略
`portalHost` 会沿用上次的值。

> 下发侧（Cloudflare Worker + 节点内容）**不在本仓库**：它持有节点订阅与放行段，
> 放在私有仓库单独维护。本仓库只需要知道"请求什么"，不需要知道"凭什么"。

## 7. 部署清单

1. 部署 Worker（私有仓库，见其 README），先上线 `/whoami`。
2. 校内实测 v4 / v6 出口地址，收敛 `ALLOWED_PREFIXES`。
3. 用 `wrangler kv key put` 写入节点 yaml（只含 `proxies`）。
4. `wrangler deploy`，`curl -6 https://<slug>.freev6.cc.cd/p` 验证 200。
5. 客户端：设置 → 备用配置 → 填门户地址 → 获取 → 启动免流。
6. 改节点只动 KV，不需要发版。
